⚡ Cache-Aside Pattern

The application code directly manages cache synchronization. It probes Redis first; on a miss, it falls back to PostgreSQL and writes back to Redis with a TTL (e.g., 3600s).

⚠️ Cache Miss Latency

Step 3 incurs an unavoidable database round-trip (~15–30ms). However, subsequent requests will hit Step 2 and return in sub-millisecond time directly from Redis memory.

🛡️ Data Consistency

By populating the cache only after a verified PostgreSQL query (Step 6), stale data is prevented and future reads are immediately accelerated.
